# プロダクト改善提案書（プロダクトマネージャ観点）

本ドキュメントは、「Manage」アプリケーションの現状のコードベース、設計書（SoftwareDesign.md）、要件定義書（Requirement.md）、およびユーザーマニュアル（UserManual.md）を精査した結果に基づき、プロダクトマネージャ（PM）の視点から今後の改善ポイントを網羅的にリストアップしたものです。

改善ポイントは、「ユーザー利便性（UX/UI）」「業務効率（リソース・プロジェクト管理）」「開発管理（システム運用・拡張性）」の3つの観点で分類しています。

---

## 1. ユーザー利便性（UX/UI・操作性の向上）

主にエンドユーザー（リソース管理者やプロジェクトマネージャ）が、いかにストレスなく直感的に操作できるかに焦点を当てた改善です。現在のローカルSPAアーキテクチャの強みをさらに伸ばす内容となります。

*   **1.1. Excelライクなキーボード操作のサポート拡充**
    *   **現状**: ガントチャートの数値入力はマウスクリックによるポップアップ入力が主体。
    *   **改善**: 十字キーによるセル間の移動、セル選択状態での直接の数値入力、`Ctrl+C` / `Ctrl+V` による複数セルのコピー＆ペースト（連続する月への稼働率一括入力など）を実装し、大量データ入力時の操作性を大幅に向上させる。
*   **1.2. 元に戻す/やり直し（Undo/Redo）機能**
    *   **現状**: ドラッグ＆ドロップによる月移動や担当者変更を行ってしまった直後に、元の状態に戻す手段がない（手動で戻す必要がある）。
    *   **改善**: `Ctrl+Z` などをトリガーとし、ローカルステートにおける直近の変更履歴をトラッキングして即座に元に戻せる機能を実装する。
*   **1.3. リアルタイム・マルチフィルタリングと検索**
    *   **現状**: テーマの一覧表示は可能だが、一覧画面で素早く目的のプロジェクトやメンバーを探し出す機能が弱い。
    *   **改善**: 画面上部にインクリメンタルサーチ付きの検索バーを常設。テーマ名、カテゴリ、担当者名、ステータス（未完了のみ等）、優先度など複数条件で即座にガントチャートをフィルタリングできるようにする。
*   **1.4. カスタムビュー（フィルター条件の保存）機能**
    *   **現状**: 毎回同じフィルタ条件（例: 「自分の部署のメンバーだけ」「特定の製品カテゴリだけ」）を設定し直す必要があるかもしれない。
    *   **改善**: よく使うフィルター・表示設定を「カスタムビュー」として保存・呼び出しできる機能を追加。

## 2. 業務効率（リソース・プロジェクト管理の高度化）

リソース管理・プロジェクト計画というビジネス目的を達成するために、データの可視化や分析、計画立案をサポートする機能の改善です。

*   **2.1. 計画と実績の比較（ベースライン・スナップショット機能）**
    *   **現状**: 常に最新の稼働率データが上書きされ、過去（例：期首や前月末）に立てた計画との差異が追えない。
    *   **改善**: 特定の時点のデータを「スナップショット（ベースライン）」として保存し、現在の状況と予実比較（差分表示）できる機能。計画変更の履歴を分析しやすくする。
*   **2.2. アベイラビリティ（空きリソース）のサジェストとスキル・ロールマッチング**
    *   **現状**: メンバーアサイン時に、誰が稼働に余裕があるかは手動で負荷表を見に行く必要がある。
    *   **改善**: テーマへのメンバー追加時に、現在指定された期間において「キャパシティに空きがある」メンバーを優先的にサジェストする機能。さらに、必要なスキルセットベースで検索できる機能をメンバーマスタに統合する。
*   **2.3. ダッシュボード（全体サマリー・統計分析）の導入**
    *   **現状**: ガントチャートとメンバー別の負荷表画面のみ。
    *   **改善**: ログイン後（起動直後）のトップ画面として、組織全体の「現在の平均稼働率」「炎上（キャパ超過）しているメンバー数」「カテゴリ別の工数比率」などをグラフで俯瞰できるダッシュボードを新設する。
*   **2.4. インポート機能による一括データ更新**
    *   **現状**: CSV/XLSXによる出力は想定・部分実装されているが、一括取り込み機能がない。
    *   **改善**: 大規模なプロジェクト編成時に外部のExcelや他システムで作成したアサインデータを一括インポート（バルクUpsert）して反映できる機能の追加。

## 3. 開発管理（システム運用・拡張性・セキュリティ）

現状は「単一ローカル実行ファイル（Single EXE）」という要件に特化していますが、利用規模の拡大やチーム運用を見据えたアーキテクチャや運用面の改善です。

*   **3.1. バックアップ・リストアとデータ保護機能のUI統合**
    *   **現状**: `database.db` ファイルを手動でコピーすることでバックアップとする運用。非エンジニアには不安が残る、あるいは忘れるリスクがある。
    *   **改善**: アプリケーション画面（管理メニュー）から、ワンクリックでデータベースのスナップショット（バックアップファイル）をダウンロード可能な機能。および、リストア機能の実装。
*   **3.2. 変更履歴（監査ログ / オーディットトレイル）**
    *   **現状**: 最新の更新日時（`updated_at`）は保持されているが、いつ、どのような値から変更されたかの履歴がない。
    *   **改善**: 重要な操作（テーマの変更、稼働率の大幅な変更、メンバーの追加/削除など）を記録するシステムログ・テーブルを設け、変更履歴をタイムラインでトレース可能にする。
*   **3.3. クラウド／C/Sアーキテクチャへの移行準備プロセス（将来構想）**
    *   **現状**: 完全ローカルのスタンドアロン動作。複数人が同時編集するとDBファイル競合や不整合が発生する。
    *   **改善**: 将来的なチーム内での同時利用を想定し、バックエンドREST APIに楽観的排他制御（ETagやバージョンカラム）を導入。WebSocketを利用した他ユーザーの更新通知（リアルタイム同期）の基礎設計の準備。
*   **3.4. ロールベースのアクセス制御 (RBAC) の導入基盤**
    *   **現状**: 管理者（admin）としての自動ログインのみで、権限の区別がない。
    *   **改善**: 将来のサーバーデプロイを見据え、「閲覧のみ（Viewer）」「一部プロジェクトの編集可能（Manager）」「全機能利用可能（Admin）」といったロールとアクセス権限（認可制御）の実装。

---

**総括**
本システムは、「導入不要で直ちに使えるポータビリティ」と「SPAによる軽快な動作」に高い価値があります。今後の改善は、このローカルアプリとしての強み（操作性の高さ）を追求しつつ（UI操作のExcel化など）、一方で、業務ツールとして必須となってくる「状態の履歴管理」や「チームスケールの運用に向けたデータガバナンス」をシームレスに組み込んでいくことがロードマップの主軸となります。
